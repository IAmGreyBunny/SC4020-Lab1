# ann-comparison

One folder for the whole ANN pipeline, run on the full **2x2 grid of
embedding model x dataset**, so the search algorithms can be compared
side by side and the model's effect separated from the dataset's:

| Config | Model | Dataset | Dim | Vectors | Gallery |
|---|---|---|---:|---:|---:|
| `vit-coco` | ViT-B/16 | COCO unlabeled2017 | 768 | 123,403 | 122,403 |
| `resnet-coco` | ResNet18 | COCO unlabeled2017 | 512 | 123,403 | 122,403 |
| `vit-zappos` | ViT-B/16 | UT-Zap50K | 768 | 50,025 | 49,025 |
| `resnet-zappos` | ResNet18 | UT-Zap50K | 512 | 50,025 | 49,025 |

Methods: Exact FlatIP (ground truth) vs LSH vs IVF-Flat vs IVF-PQ vs
HNSW vs HNSW-PQ, with Recall@K, Precision@K and mAP@K (K = 5/10/20),
latency, QPS, build time and index size. IVF and HNSW each run with and
without product quantization (PQ), so the effect of the index structure
(clusters vs graph) and of compression can be read separately.

**Why the 2x2 grid:** the original experiments paired each dataset with
one model (ViT on COCO, ResNet18 on Zappos), so a difference between them
could come from either. Here both models are run on both datasets. Both
models on a dataset have the same rows in the same order, so the seed-42
split gives them the **identical 1,000 queries**; any difference between
the two is due to the model alone.

This folder merges `experiments/vit-coco-faiss/` and
`experiments/resnet18-zappos/`, which are left unchanged. The corruption
robustness test (`pipeline/corruption.py`, presented in Section 8 of the
notebook) is included here too: it corrupts only the query, re-uses the
benchmark's held-out queries and the clean embeddings already on disk, and
reports retrieval quality as well as embedding drift. The former
`experiments/robustness-comparison/` experiment is retired (see its README).

## Pipeline

```text

            \                         /
   pipeline/extract_embeddings.py --model {vit,resnet} --dataset {coco,zappos}
             |  ViT-B/16 (768-d) or ResNet18 (512-d), L2-normalized
             v
   data/circo/{vit,resnet}_*.npy     data/zappos/{vit,resnet}_*.npy
             |                         |
             +------------+------------+
             |                         |
    benchmark_ann.py --config all   pipeline/corruption.py --config all
             |                         |   (corrupt queries, exact search)
             v                         v
    results/<config>/ann_results.*   results/<config>/robustness/
    results/combined_ann_results.csv corruption_*.csv + cached corrupted queries
             |                         |
             |                         v
             |            pipeline/index_robustness.py --config all
             |                         |   (rebuild IVF/HNSW indexes, reuse cache)
             |                         v
             |            results/<config>/index_robustness/
             |            results/index_robustness_combined.csv
             \                         /
              \                       /
    compare_methods.ipynb   (Sections 1-7 ANN; Section 8 corruption:
                            Ground-Truth Shift + ANN index view)
    index_robustness.ipynb  (standalone companion to the Section 8 index view)
```

## Step 2 - Extract the embeddings (GPU recommended)

One command per configuration, from the repository root. Each run is
resumable - re-running the same command continues where it stopped.
Times are rough for an RTX 4060 laptop GPU:

```bash
python experiments/ann-comparison/pipeline/extract_embeddings.py --model resnet --dataset zappos  # ~3 min
python experiments/ann-comparison/pipeline/extract_embeddings.py --model vit    --dataset zappos  # ~10 min
python experiments/ann-comparison/pipeline/extract_embeddings.py --model resnet --dataset coco    # ~10 min
python experiments/ann-comparison/pipeline/extract_embeddings.py --model vit    --dataset coco    # ~25 min
```

Outputs (`.npy` is git-ignored): `data/<circo|zappos>/<model>_embeddings.npy`
(float32, L2-normalized), `<model>_image_ids.npy` (int64) and
`<model>_metadata.json`. Each run reloads its output and checks shape,
dtype, finiteness and unit norms before printing `DONE`.

Notes:

- `--model resnet --dataset zappos` overwrites the teammate's handoff
  `data/zappos/resnet_embeddings.npy` with an identical regeneration. To


## Step 3 - Run the benchmark

```bash
# all four configs (any whose embeddings are missing is skipped)
python experiments/ann-comparison/benchmark_ann.py            # ~20-30 min total

# or one at a time
python experiments/ann-comparison/benchmark_ann.py --config resnet-zappos
```

Every run rebuilds `results/combined_ann_results.csv` from all available
`results/*/ann_results.json`.

The protocol is identical for every configuration: 1,000 held-out
queries (seed 42), exact top-20 ground truth, single-threaded search,
all-core builds, the same LSH / IVF / HNSW sweeps. The only differences
are forced by the data and live in `datasets.py`:

- `pq-m` 48 for ViT (768-d) and 32 for ResNet18 (512-d), because FAISS
  needs `dimension % pq_m == 0`.
- IVF-Flat, IVF-PQ and HNSW-PQ train on the same 50k gallery sample for
  COCO and on the full gallery (49,025 rows) for Zappos.

Searches are timed single-threaded. The script also pins the BLAS thread
pool (`OPENBLAS_NUM_THREADS` / `MKL_NUM_THREADS` = 1), because exact
search runs through BLAS, which ignores FAISS's own thread setting.
Without the pin, exact search silently used every core on Windows and
looked faster than HNSW.

### Metrics

All accuracy metrics treat the **exact top-K of the same configuration**
as the relevant set for each query, at K = 5, 10 and 20:

- **Recall@K**: the fraction of the exact top-K that the method also
  returns.
- **Precision@K**: the fraction of the method's top-K that is in the
  exact top-K. Both lists hold K items, so it is numerically equal to
  Recall@K here. It is reported separately for completeness.
- **mAP@K**: the mean over queries of
  AP@K = (1/K) · Σ<sub>i≤K</sub> Precision@i · rel(i).
  It is rank-aware: true neighbours returned lower down the list score
  less.

Exact search scores 1.0 on all three by definition. Padding (`-1`, no
result returned) never counts as relevant.

Outputs per configuration in `results/<config>/`:

| File | Contents |
|---|---|
| `ann_results.json` / `.csv` | per method/setting: Recall/Precision/mAP @5/10/20, latency, QPS, build time, index size |
| `per_query/exact_top20.npy` | exact top-20 gallery rows per query (ground truth) |
| `per_query/<setting>_top20.npy` | top-20 per ANN setting (`lsh_nb*`, `ivfflat_np*`, `ivfpq_np*`, `hnsw_ef*`, `hnswpq_ef*`) |
| `per_query/query_rows.npy`, `gallery_rows.npy` | the fixed split |
| `visual-comparisons/` | same-query grids (from the notebook) |

## Step 3b - Corruption robustness (optional, after Step 3)

Answers a question embedding drift alone cannot: when the **query image** is
corrupted (gallery stays clean), does the search still return the same
neighbours? It re-uses the benchmark's held-out queries and the clean
embeddings, so it only embeds the corrupted variants.

```bash
# all four configs, 200 of the benchmark queries, every transform
python experiments/ann-comparison/pipeline/corruption.py --config all --num-queries 200

# one config, a subset of transforms
python experiments/ann-comparison/pipeline/corruption.py --config vit-zappos \
  --transforms rotation,blur --num-queries 200
```

Protocol: the query is corrupted (`pipeline/perturbations.py`); the clean
query is kept as the `original` level. Exact FlatIP search over the clean
gallery. Ground truth is the **clean query's** exact top-20 neighbours, so the
two metrics separate cleanly:

- **Embedding drift** - `cosine(clean, corrupted)` (the old robustness metric).
- **Rank stability** - `Recall@K` / `Precision@K` / `mAP@K` of the corrupted
  query against that ground truth. mAP is rank-aware, so a reordering the
  drift metric misses still shows up.

Outputs per config in `results/<config>/robustness/`:
`corruption_per_query.csv` (one row per query/variant), `corruption_summary.csv`
(mean/std per transform/level), `corruption_params.json`, plus a cached
`corrupted_query_embeddings.npy`. Across configs:
`results/robustness_corruption_combined.csv`. `--num-queries` takes a
reproducible subset of the benchmark queries so the run stays cheap while
remaining comparable to the ANN results.

## Step 3c - ANN index robustness (optional, after Step 3b)

Step 3b measures the *model* (exact search only). This step measures the
*indexes*: it rebuilds **IVF-Flat, IVF-PQ, HNSW and HNSW-PQ** with the main
benchmark's construction parameters (recovered from `ann_results.json`) and
searches them with the corrupted queries cached by Step 3b - the same vectors,
the same queries and the same exact references, so nothing is recomputed.
LSH is out of scope, and Exact FlatIP is the reference of every metric rather
than a competitor.

```bash
# all four configs (any whose corruption cache is missing is skipped)
python experiments/ann-comparison/pipeline/index_robustness.py

# one config, only some of the indexes
python experiments/ann-comparison/pipeline/index_robustness.py --config vit-zappos \
  --methods ivfflat,hnsw
```

Each index is searched at the knee-score setting (`scoring.knee_score`) of its
full-vector partner - IVF-Flat and IVF-PQ share `nprobe`, HNSW and HNSW-PQ
share `efSearch` (the `pq_sweep.py` convention, so every PQ index is compared
with its uncompressed version at the same search effort). `--nprobe` /
`--ef-search` override the picks.

Three metric families per query variant, at K = 5/10/20:

- **fidelity** - ANN on the corrupted query vs *exact search of that same
  corrupted query*: pure ANN approximation error under corruption.
- **end_to_end** - ANN on the corrupted query vs the *clean query's* exact
  neighbours: total retrieval degradation (model + index).
- **stability** - ANN on the corrupted query vs the *same index* on the clean
  query: how much the index's own output changes.

The `original` level anchors the sanity checks: stability is exactly 1.0 (the
index is compared with itself) and fidelity equals end-to-end. The script also
verifies that its recovered gallery reproduces the cached exact reference
before searching anything.

Outputs per config in `results/<config>/index_robustness/`:
`index_robustness_summary.csv` (mean/std per algorithm x transform x level),
`index_robustness_params.json` (settings, sources, self-checks) and
`per_query/` (one row per algorithm x variant plus per-method top-K arrays;
local only). Across configs: `results/index_robustness_combined.csv`.

## Step 4 - Compare in the notebook

```bash
cd experiments/ann-comparison
jupyter lab   # open compare_methods.ipynb, run all cells
```

Sections:

1. one combined metrics table for all four configurations,
2. overlaid trade-off plots (colour = method, marker = dataset,
   filled = ViT / hollow = ResNet) and parameter sweeps,
3. cross-configuration summary with speed-up and compression vs exact,
4. **model vs dataset effects**: each method across the 2x2 grid, with
   "model effect" (ViT - ResNet) and "dataset effect" (COCO - Zappos)
   columns, plus how much the two models' exact neighbours overlap,
5. the same query searched by both models' exact search and every ANN
   method (`SAME`/`DIFF` marks where the models disagree),
6. Zappos category / subcategory precision@10 for both models,
7. sanity checks (incl. that both models used identical queries),
8. **corruption robustness** (Steps 3b + 3c): one corrupted-query sweep,
   measured with exact search (the **Ground-Truth Shift** baseline: embedding
   drift and Recall@K / mAP@K vs corruption intensity, per transform, all
   four configurations) and with the ANN indexes - IVF-Flat and HNSW at
   their knee settings - whose **Fidelity**, **End-to-End** (with the
   Ground-Truth Shift overlaid) and **Stability** are plotted the same way,
   plus example corrupted queries (the Step 3c results also cover the PQ
   variants; `ALGORITHMS` in the index-view setup cell selects which are
   shown).

Sections 1-4 work from `ann_results.json` alone. Sections 5-7 need the
local `per_query/` files, the embeddings and the images; anything missing
is skipped with a note. Section 8 needs the
`results/<config>/robustness/` files from Step 3b for the Ground-Truth
Shift (the example grid also needs its per-variant local files) and the
`results/<config>/index_robustness/` files from Step 3c for the index
view. `index_robustness.ipynb` is a standalone companion to the index view of
Section 8 reading the same files.

## Results

Not committed yet - run steps 2-4 to populate `results/`. The previous
single-model numbers (ViT/COCO from the original WSL machine, ResNet/
Zappos re-run here) are in this branch's git history.

When reading the results:

- Compare **speed-ups**, not raw milliseconds, across configurations:
  latency depends on gallery size (COCO is 2.5x larger) and vector
  dimension (768 vs 512).
- ResNet18 cosine scores are much higher than ViT's (often 0.6-0.8 vs
  0.1-0.4) because its features are post-ReLU and therefore non-negative.
  Only the ranking matters for every metric here, so this does not bias
  the comparison.
- Expected from the earlier single-model runs: HNSW dominates the
  speed-accuracy trade-off and its mAP equals its recall (it ranks with
  exact distances); IVF-PQ and LSH lose more on mAP than on recall
  because they rank with approximate distances.

## Notes

- Vectors are L2-normalized, so `IndexFlatIP` computes cosine similarity
  directly; `IndexLSH` and `IndexHNSWPQ` rank by L2, which equals cosine
  ranking on normalized vectors. (`IndexHNSWPQ` is left on L2 because
  with `METRIC_INNER_PRODUCT` it returns wrong neighbours in FAISS 1.15.)
- Dataset links are conveniences for this working repository only. The
  final project submission ZIP must contain no datasets, models or
  cloud-hosted links (course requirement).
